# Pinned flowchart shape math check

The pinned Mermaid 12 `chunk-7INBJB4K.mjs` registry at lines 6257–6742 defines 53 canonical `shortName` shapes. Its alias map adds 97 distinct aliases (150 unique documented keys total), and `undocumentedShapes` adds 27 more cross-diagram/internal keys. FlowDB's `isValidShape` checks this map; `getTypeFromVertex` in `chunk-7M6MHVWA.mjs:844` returns a metadata `shape:` value unchanged apart from legacy `square`/`round`/`ellipse` paths and icon/image properties. Visser blocks authored `icon:` and `img:` metadata (`rules.ts` and `flowchart-metadata.ts`); `shape: icon` alone does not specify an external icon and passes this source rule. The browser matrix below exercised **all 53 canonical names and six lowercase undocumented metadata names** (`state`, `choice`, `note`, `composite`, `icon`, `anchor`). Syntactic acceptance of other registered keys is not evidence of rendered math coverage.

Every source passes Visser's `checkMermaidSource`. Each label contains a tall nested fraction and `\rlap{\rule{20em}{1em}}x`. For the 50 text-bearing shapes, all 200 render cases retained both attested TeX strings, had the native formula owner on the inner foreignObject, positive label/viewBox dimensions, and kept descendant math ink inside the reserved label, node group, and SVG bounds. The shapes cover curved, stacked, document-wave, open-brace, text-only, icon-shaped-without-external-icon, and other non-rectangle drawing paths. The test also verifies that a plain no-label shape in a math-bearing diagram does not claim its neighboring node's formula.
